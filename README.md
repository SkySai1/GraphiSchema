# GraphiSchema

Локальный редактор архитектурных диаграмм для macOS: компоненты, контейнеры и связи можно изменять на холсте, через JSON/DOT или с помощью Ollama. Нативный интерфейс построен на Swift/AppKit, бизнес-логика — на Python/FastAPI, компоновка — на Graphviz. Все способы редактирования используют общую JSON-модель проекта.

## Запуск

### Требования

- macOS 13+; для сборки — Swift 5.9+ и Xcode Command Line Tools.
- `uv` и Python 3.11+ для локального backend.
- Graphviz для всех движков компоновки. Без него доступна упрощённая резервная компоновка.
- `librsvg` с утилитой `rsvg-convert` для экспорта PNG.
- Ollama с загруженной моделью — только для функций ИИ.

Если инструменты разработки ещё не установлены, выполните `xcode-select --install`. При использовании Homebrew остальные зависимости устанавливаются командой:

```bash
brew install uv graphviz librsvg
```

### Сборка и открытие приложения

Из корня репозитория:

```bash
./scripts/build_macos.sh local
open "dist/GraphiSchema.app"
```

Скрипт собирает приложение и устанавливает Python-зависимости. При запуске появляется окно ожидания, пока локальный backend не подтвердит готовность и приложение не загрузит проект. При обычном выходе сначала сохраняются проекты, затем backend получает запрос на штатное завершение. Клиент отправляет keepalive каждые 20 секунд; backend завершится, если минуту не получает keepalive ни от одного клиента. Если подключены другие клиенты, сервер продолжает работать для них. Отдельный терминал или браузер для работы не нужны. Если приложение уже собрано, используйте только команду `open` или откройте `.app` в Finder.

Иконка в Finder, Dock и шапке рабочего окна использует единый исходник `resources/app-icon/GraphiSchema.png`. При сборке `scripts/build_app_icon.sh` создаёт `.icns` с обычными и Retina-размерами 16–1024 px средствами macOS; дополнительных библиотек для этого не нужно. Отдельно получить иконку можно командой `./scripts/build_app_icon.sh` — результат сохранится в `dist/GraphiSchema.icns`.

При первой установке зависимостей может потребоваться интернет. После установки редактор и коллекции работают локально. Для запуска готового `.app` на другой машине также нужен `uv` и зависимости соответствующих функций.

## Мини-руководство

Рабочее окно разделено на библиотеку объектов слева, холст в центре, JSON/DOT справа и чат ИИ снизу. Панели можно скрывать через меню **Вид**.

1. **Начните проект.** Откройте JSON через **Файл → Открыть проект…** (`Cmd+O`) или выберите **Файл → Загрузить базовый шаблон…**. Название меняется в верхней части окна.
2. **Добавьте компоненты.** Найдите фигуру в левой коллекции и перетащите на холст. Для пустого контейнера нажмите ПКМ по свободному месту → **Создать пустой контейнер**. Свободный компонент прикрепляется при переносе внутрь контейнера; извлечение выполняется через его контекстное меню **Извлечь из контейнера**.
3. **Соедините объекты.** Выделите компонент и перетащите круглый маркер с горизонтальной стрелкой на другой компонент. Щелчок по линии выделяет её; точки начала и конца позволяют переприкрепить связь. Полые маркеры в серединах участков добавляют точки маршрута, а двойной щелчок открывает текст. Контейнеры соединяются таким же маркером со стрелкой.
4. **Настройте оформление.** Выделите объект или связь и нажмите **Стиль**, либо откройте **Настройки → Выделенный объект…**. Здесь меняются фигура, цвета, прозрачность, текст и параметры линии. **Настройки → Настройки проекта…** открывает все общие параметры независимо от выделения: название, направление, маршрутизацию, фон, прозрачность подписей новых связей, тему и компоновку. Пункт объекта недоступен, когда ничего не выделено. Значки `?` рядом с полями показывают справку при наведении.
5. **Сохраните результат.** **Файл → Сохранить проект** (`Cmd+S`) записывает JSON-файл. Текущее состояние также сохраняется автоматически в локальную базу. Через **Файл → История версий…** можно сравнивать и восстанавливать снимки. При выборе версии в списке справа загружается её диаграмма для просмотра с масштабированием, навигацией и кнопкой **Вписать**. Выбор и закрытие истории не заменяют текущий проект и не применяют черновики кода. Для замены состояния нажмите **Восстановить** и подтвердите действие; последующие версии останутся в истории. При незавершённом черновике JSON или предложении ИИ/DOT просмотр доступен, а для восстановления сначала примените или отмените эти изменения.
6. **Экспортируйте схему.** Выберите **Файл → Экспортировать SVG…**, **Экспортировать PNG…** или **Экспортировать PDF…**. PDF открывается в отдельном окне с предпросмотром и настройками; сохранение записывает именно показанный документ. PDF всегда создаётся в светлом оформлении на белом фоне, включая подписи и легенду; тема рабочего окна и сохранённого проекта при этом не меняется.

### Пересечения, поворот, типы и ручная легенда

- **Перемычки линий.** В месте пересечения верхняя линия получает дугу. Порядок определяется z-index связи; при равных значениях — порядком связей в проекте. ПКМ по линии → **Линию на передний/задний план** или **Z-index линии…**. Точное значение также доступно в свойствах связи. Касания, совпадающие участки и соединения у концов не превращаются в перемычки. Маршруты и наконечники при этом не изменяются.
- **Пустые подписи.** Текст фигуры, контейнера или связи можно полностью удалить. В **Настройки → Настройки проекта…** выключите **Подписывать новые элементы**, чтобы новые элементы сразу создавались без текста. В списке слева такой элемент обозначается ID; этот ID не рисуется на фигуре.
- **Вращение.** Выделите фигуру и потяните круглый маркер `↻` над ней; `Shift` задаёт шаг 15°. Доступны жест вращения двумя пальцами на тачпаде, поле **Поворот, °** и команды ПКМ. Группа вращается синхронно: каждый объект вокруг своего центра. Текст, точки крепления и область нажатия поворачиваются вместе с фигурой. Вращение сохраняется при копировании и экспорте.
- **Типы связей.** Откройте **Настройки → Типы связей…**. Создайте тип с постоянным ID, названием, описанием и стилем либо возьмите стиль выделенной линии кнопкой **Из выделенной связи**. Сохранение обновляет все связи этого типа. В свойствах одной или нескольких связей выберите **Тип связи**. Индивидуальная правка стиля отключает связь от общего типа, сохраняя внешний вид; изменение подписи, концов или z-index сохраняет тип. Удаление типа оставляет его связи с текущим оформлением.
- **Конструктор легенды.** **Настройки → Конструктор условных обозначений…** открывает таблицу: символ слева, описание справа. Добавляйте объекты с холста, фигуры коллекции и типы связей, меняйте порядок строк. Для типа автоматически используется его описание; кнопка **Автоописание** возвращает его после ручной правки. В ручном режиме таблица попадает в SVG/PNG и в PDF при включённой легенде. Длинная легенда PDF переносится на следующие страницы; режим **Автоматическая легенда** сохраняет прежний способ формирования.

У прямых и прямоугольных маршрутов нет отдельного обязательного отрезка у фиксированного порта: изгибы рассчитываются от фактической точки крепления. Прямоугольный маршрут сохраняет углы 90°. Прямая с вручную выбранной дальней стороной может пройти через объект — выберите ближайшую сторону, прямоугольный маршрут или задайте промежуточные точки для обхода.

Поворот, порядок линий, перемычки и конструктор легенды реализованы геометрией/рендерером GraphiSchema поверх Graphviz. В DOT сохраняются расширения `gs_rotation`, `gs_z_index`, `gs_type_id`, `gs_edge_types`, `gs_legend_mode`, `gs_legend_entries`, `gs_label_new_elements`, `gs_groups`; сторонний Graphviz игнорирует их. JSON-файлы, история и ветки сохраняют все эти данные.

### Контейнеры, маршруты и постоянные группы

Контейнер может быть источником и целью связи: **контейнер ↔ контейнер** и **контейнер ↔ компонент**. Выделите контейнер и потяните круглый маркер со стрелкой на второй элемент. При переприкреплении начала/конца готовой линии контейнеры также подсвечивают точки крепления. В свойствах связи источники и цели включают оба вида элементов. Стрелки крепятся к видимой рамке, в том числе к скруглённым углам; изменение размеров и перемещение контейнера обновляют связь.

**Двойной щелчок** по фигуре, контейнеру или линии открывает редактор текста. Длительное удерживание больше не вызывает окон. Редактирование через ПКМ сохранено.

У выделенной линии заполненные точки обозначают существующие изгибы, полые — места добавления. Потяните полый маркер или щёлкните по нему: участок разделится, и в серединах новых участков появятся следующие маркеры. Новые точки можно добавлять с обеих сторон любого изгиба, до 32 точек на связь. Одиночный щелчок подтверждается после интервала распознавания двойного, поэтому двойной щелчок открывает текст без добавления изгиба. Точки перетаскиваются; **Сбросить маршрут** в ПКМ удаляет их, `Cmd+Z` отменяет изменение.

Для **постоянной группы** выделите несколько фигур и нажмите `Cmd+G` или ПКМ → **Сгруппировать**. Группа хранится в JSON и истории; щелчок по участнику выделяет всю группу. Перемещение, масштабирование, копирование, удаление и групповое оформление применяются совместно. Внутренние ручные маршруты перемещаются вместе с группой. Имя меняется в свойствах выделенной группы; `Cmd+Shift+G` или **Разгруппировать** возвращает независимый выбор. Группируются фигуры внутри одного контейнера либо фигуры вне контейнеров; для объединения элементов из разных контейнеров сначала приведите их к общему контейнеру. В PDF настройка **Сохранять группы** удерживает их взаимное размещение при коррекции наложений и увеличении интервалов. Рамки групп можно включить отдельно в PDF, SVG и PNG.

### PNG и SVG

**Файл → Экспортировать SVG…** сохраняет векторный файл. В окне сохранения доступны флажки легенды и рамок групп.

**Файл → Экспортировать PNG…** открывает окно с предпросмотром. Задайте фактическую ширину и высоту в пикселях либо быстрый размер по ширине. При включённых пропорциях высота учитывает диаграмму и легенду; при выключенных изображение вписывается в выбранный прямоугольник с полями без деформации.

- Размер: 64–16384 px на сторону, не более 64 мегапикселей. При включённых пропорциях размер большой или вытянутой схемы подгоняется автоматически. При независимых ширине/высоте используйте **Подогнать размер**.
- **Качество:** стандартное 1× либо адаптивное сглаживание 2×. PNG остаётся форматом без потерь; 2× отрисовывает увеличенную копию и уменьшает её до заданных пикселей. Для большого файла автоматически применяется 1× без уменьшения выбранного разрешения, чтобы промежуточный растр укладывался в ограничения памяти.
- **DPI:** 72–600, метаданные для печати. Количество пикселей задаётся независимо.
- **Фон:** тема проекта, белый, прозрачный либо тёмный. Белый/тёмный вариант переключает автоматические цвета для контраста.
- **Легенда:** автоматическая или собранная вручную таблица проекта, без потери строк.
- **Рамки групп:** отдельный флажок. Положение объектов сохраняется при изменении разрешения.

Предпросмотр обновляется при смене параметров, включая легенду и рамки групп. Он ограничен 1200 × 900 px для быстрой работы; **Сохранить PNG…** формирует файл в полном выбранном разрешении с тем же снимком схемы и параметрами. Пока размер или DPI заполнены неверно, сохранение отключено с пояснением, но предпросмотр продолжает обновляться. Для получения новых изменений холста нажмите **Обновить из схемы**. Экспорт не сохраняет дополнительные версии и не меняет исходную диаграмму.

### PDF: предпросмотр и подготовка к печати

На вкладке **Страница** независимо включаются заголовок проекта, имя текущей ветки, номера страниц и **Watermark GraphiSchema**. Имя ветки размещается отдельной строкой, watermark — в нижней полосе; отключение нумерации не меняет состояние watermark.

1. Примените или отмените незавершённые изменения JSON/DOT и предложения ИИ, затем откройте **Файл → Экспортировать PDF…**. Приложение получает актуальную геометрию применённой схемы без сохранения дополнительных версий.
2. Выберите пресет или измените параметры в трёх вкладках. Предпросмотр обновляется после ввода; справа доступны **Вписать**, **100%**, увеличение, уменьшение и переход между страницами. Масштаб просмотра не меняет масштаб печати.
3. Проверьте размеры бумаги, минимальный итоговый размер текста и сведения о пересечениях под предпросмотром. Для больших схем используйте A3/A2, отдельную страницу легенды или формат **По размеру схемы**.
4. Нажмите **Сохранить PDF…**. Файл содержит уже сформированные страницы предпросмотра, без повторного расчёта диаграммы при сохранении.

| Вкладка | Настройки |
|---|---|
| **Страница** | A5/A4/A3/A2/Letter, ориентация, собственные размеры в мм, поля, заполнение области, заголовок, номера страниц, легенда справа или отдельно |
| **Стиль** | Раздельная толщина фигур, контейнеров и связей; размер наконечников; размер текста фигур и связей, заголовков контейнеров; фон подписей и контраст текста |
| **Размещение** | Раздвижение пересекающихся фигур и групп, интервалы и минимальный промежуток, подгонка фигур под текст с сохранением пропорций, перенос слов, размещение подписей связей вне занятых областей |

Сцена формируется в векторном виде при 72 pt/in, а затем целиком вписывается в страницу одним коэффициентом. Фигуры, текст, линии, наконечники и внутренние отступы масштабируются согласованно. Заголовок и легенда занимают отдельные области бумаги. Если легенда длинная, создаются дополнительные страницы без удаления строк.

Размещение и стили корректируются в **экспортной копии**. Фигуры увеличиваются пропорционально, контейнеры перемещаются вместе с содержимым, для заголовков резервируется отдельная полоса. Подписи связей избегают фигур, заголовков и других подписей; при заметном смещении получают тонкую выноску. Если свободного места не удалось найти, это отмечается под предпросмотром — можно увеличить интервалы или нажать **Автокомпоновка копии**. Она использует выбранный движок Graphviz и сбрасывает ручные маршруты только в экспортной копии. **Обновить из текущей схемы** возвращает актуальное расположение с холста. Исходный проект, его история и координаты не меняются; открытие PDF-экспорта на пустом холсте не регистрирует проект.

### Быстрые настройки через ПКМ

| Элемент | Параметры в контекстном меню |
|---|---|
| Фигура | Цвет заливки, контура и текста; сплошной, пунктирный или точечный контур; толщина контура |
| Контейнер | Цвет заливки, границы и текста; толщина границы |
| Связь | Цвет линии и подписи; стиль, толщина и маршрут; наконечники у источника и цели; направление и смена начала/конца |

Меню отмечает текущие значения. Если выделено несколько фигур, стиль и толщина применяются ко всем одним действием; различающиеся значения отмечаются прочерком. Цвет открывает соответствующее окно редактора цветов. Изменения сохраняются в проекте, отражаются в DOT и доступны для отмены/повтора.

Толщина задаётся в пунктах (0,5–10); произвольное значение доступно в свойствах элемента. Пресет связи **Жирная** устанавливает не менее 3 pt. Выбор наконечника у источника включает направление в обе стороны; выбор направления включает отсутствующие наконечники. Контуры фигур используют Graphviz `style`, а толщина фигур, связей и контейнеров — `penwidth`. [Стили Graphviz](https://graphviz.org/docs/attr-types/style/), [толщина линий](https://graphviz.org/docs/attrs/penwidth/).

### Управление холстом

| Действие | Управление |
|---|---|
| Переместить холст | Прокрутка тачпада или `Option` + перетаскивание |
| Приблизить / отдалить | Щипок на тачпаде, `Cmd` + прокрутка или кнопки масштаба |
| Показать всю схему | Кнопка **Вписать** |
| Показать / скрыть сетку | **Вид → Сетка**; галочка показывает состояние в текущем окне |
| Разместить объекты автоматически | Кнопка **Автокомпоновка** на панели холста |
| Выделить несколько компонентов | Рамка выделения или `Shift` + щелчки |
| Изменить размер компонента / группы | Перетаскивание круглого маркера с двумя треугольниками по диагонали |
| Растянуть фигуру по ширине / высоте | Маркеры на сторонах и углах; `Shift` на углу сохраняет пропорции |
| Изменить размер текста | **Стиль → Размер текста, pt** или окно редактирования текста через ПКМ |
| Включить перенос слов | **Стиль → Перенос строк** или флажок в окне текста фигуры |
| Удалить выбранные объекты | `Delete` или `Fn+Delete`, когда холст в фокусе |
| Скопировать / вставить объекты | `Cmd+C` / `Cmd+V`, когда холст в фокусе |
| Дублировать с новыми ID | `Cmd+D`, ПКМ → **Дублировать** или `Cmd` + перетаскивание |
| Переместить / скопировать по одной оси | Удерживать `Shift` во время перетаскивания; ось выбирается по первому движению |
| Редактировать текст фигуры | ПКМ или двойной щелчок по фигуре |
| Сгруппировать / разгруппировать | `Cmd+G` / `Cmd+Shift+G` или ПКМ |
| Отменить / повторить изменение | `Cmd+Z` / `Cmd+Y` |

По умолчанию холст следует за пальцами по обеим осям. **Настройки → Инверсная прокрутка тачпада** меняет оба направления на противоположные. Цветовая тема выбирается в **Настройки → Цветовая тема**: системная, светлая или тёмная. Режим запоминается отдельно для ID проекта; ручная тема входит в снимок ветки, системная отслеживает оформление macOS.

### Графическая привязка связей

Создавайте связь боковой стрелкой выбранной фигуры. Во время перетаскивания у доступных объектов появляются точки на сторонах и вершинах их видимого контура. Отпустите указатель на точке для фиксированной привязки или на другой части объекта для автоматического выбора ближайшей границы. Подсвеченная точка и подпись рядом с указателем показывают будущую привязку; маршрут обновляется до отпускания. Источник новой связи всегда использует ближайшую границу.

У готовой связи выделите линию и перетащите зелёную точку начала или оранжевую точку конца. Так можно сменить сторону, вершину или сам объект, включая источник. Для возврата к автоматической привязке перенесите конец на тело фигуры, минуя точки. Перенос между точками той же фигуры сохраняет ручные изгибы; смена объекта сбрасывает их. Отпускание на пустом месте и `Esc` отменяют перенос. Изменения сохраняются в общей истории и отменяются через `Cmd+Z`.

### Текст фигуры

Откройте **Редактировать текст…** через ПКМ или двойной щелчок по фигуре. Подпись, размер, выравнивание и положение текста применяются сразу при изменении полей; кнопка **Готово** закрывает окно. Подпись и размер текста в свойствах также обновляются во время ввода. Допустимы размеры 1–144 pt; неполное или некорректное значение оставляет последнее допустимое состояние.

Опция **Переносить текст по ширине фигуры** переносит слова автоматически, включая разбиение длинных слов. `Enter` в многострочном поле добавляет ручной перевод строки независимо от этой опции. Если текстовый блок не помещается по высоте, увеличьте фигуру. Перенос, ручные переводы строк и параметры текста сохраняются в проекте и учитываются при экспорте; изменения проходят через общую историю.

Окна свойств, текста, цветов, Ollama и переменных промпта появляются рядом с курсором на текущем мониторе. У границы экрана окно смещается так, чтобы оставаться доступным целиком.

Окна стилей и свойств, редакторы текста и цветов остаются поверх рабочих окон при взаимодействии с холстом. При переключении на другое приложение эти панели временно скрываются; закрытие рабочего окна закрывает связанные с ним панели.

### Текст при групповом выделении

Выделите несколько фигур рамкой или с `Shift`, затем нажмите **Стиль** либо **Настройки → Выделенный объект…**. В разделе **Текст группы** доступны общий размер 1–144 pt, выравнивание влево/центр/вправо, размещение сверху/посередине/снизу и перенос строк. Цвет текста меняется общим цветовым редактором.

Для группы связей доступны общий размер подписи, цвет и прозрачность фона. Размер связей хранится в `edges[].style.font_size` и Graphviz `fontsize`; прежний размер по умолчанию — 9 pt. Он применяется на холсте и при экспорте SVG/PNG/PDF.

Если параметры элементов различаются, поле размера и списки показывают **Разные значения**, а флажки — прочерк. Ввод или выбор сразу применяет соответствующий параметр ко всей группе. Групповые правки сохраняются через общую историю и доступны для `Cmd+Z` / `Cmd+Y`.

### Цвета активного объекта

Через меню **Настройки**, ПКМ на объекте или цветовой образец в свойствах откройте нужное окно:

| Параметр | Горячая клавиша |
|---|---|
| Фон / заливка | `Cmd+Option+F` |
| Граница / линия связи | `Cmd+Option+B` |
| Текст | `Cmd+Option+T` |

Каждый параметр имеет одно отдельное окно. Повторный вызов поднимает существующее; название содержит параметр и текущий объект. При смене выделения окна обновляются автоматически. Доступны палитра, RGB, непрозрачность и HEX (`#RRGGBB` / `#RRGGBBAA`); изменения применяются сразу, сохраняются и отменяются через `Cmd+Z`.

При групповом выделении цвет применяется ко всем выбранным фигурам. ПКМ по пустому холсту позволяет изменить фон проекта. У связей настраиваются цвет линии и подписи. Неприменимые параметры в открытых окнах недоступны. Режим **Свой цвет** сохраняет RGBA при смене темы. **Чёрный / белый по теме** делает фон белым днём и чёрным ночью, текст и границу — наоборот; **Инверсия** меняет эту пару местами. Новые элементы создаются в автоматическом режиме. Ручной выбор цвета отключает автоматику только у выбранного параметра. Карандаши дополняют HSV/RGB/HEX; вкладка **Цвета проекта** хранит до 64 образцов вместе с прозрачностью и историей. ПКМ по образцу удаляет его.

Для подписи стрелки в свойствах связи есть переключатель **Прозрачный фон подписи**. При включении видны линия и объекты под текстом; при выключении добавляется непрозрачная плашка в цвете темы. Он доступен и при групповом выделении связей: прочерк показывает разные значения, переключение задаёт одно значение всей группе. Через ПКМ на связи или группе также доступно **Фон подписи → Прозрачный / Непрозрачный**. Изменение применяется сразу, сохраняется в JSON/DOT и истории, отменяется одной операцией и учитывается в SVG/PNG. В окне PDF-экспорта фон можно переопределить: по умолчанию используется белая плашка, а вариант **Как в проекте** сохраняет индивидуальные значения связей.

В свойствах проекта есть **Прозрачный фон новых связей**. Для нового проекта опция включена; новые связи на холсте, в DOT и предложениях ИИ получают выбранный фон, если он не задан явно. Настройка хранится в `presentation.default_edge_label_background_transparent` и расширении DOT `gs_default_edge_label_background_transparent`. Уже созданные связи сохраняют индивидуальное значение; изменить их можно групповым выделением. Подписи старых файлов сохраняют прежнее оформление.

## Функциональность

- **Графический редактор:** стандартные фигуры и локальные SVG-коллекции Tabler/Lucide, вложенные контейнеры, групповое перемещение, удаление и масштабирование, порядок наложения объектов.
- **Границы фигур:** сплошные, пунктирные и точечные, толщиной 0,5–10 pt. Длина штрихов и промежутки между ними растут пропорционально толщине, сохраняя разрывы на холсте и в SVG/PNG/PDF. Это относится и к внутренним линиям иконок.
- **Заголовки контейнеров:** базовые 11 pt на холсте, в предпросмотре истории и при экспорте SVG/PNG. Для названия выделяется отдельная полоса 28 pt над содержимым; родительский контейнер учитывает рамки и заголовки вложенных контейнеров, включая пустые. В PDF базовый размер можно переопределить: полоса заголовка пересчитывается, затем вся сцена масштабируется пропорционально. Длинные названия сокращаются многоточием в пределах рамки, полный текст хранится в проекте. В DOT размер закреплён через [`fontsize=11`](https://graphviz.org/docs/attrs/fontsize/).
- **Размеры и текст:** независимое растягивание фигуры по ширине и высоте (`width`/`height`), размер подписи 1–144 pt (`fontsize`), опциональный перенос слов и многострочное редактирование с обновлением холста при вводе. Размеры и текст сохраняются в JSON/DOT и применяются при экспорте. Копирование контейнера включает вложенные контейнеры, компоненты и внутренние связи с новыми ID.
- **Связи:** прямые, ломаные, прямоугольные и кривые маршруты; цвета, подписи и наконечники; привязка к контуру, стороне или вершине. **Оптимизировать линии** сбрасывает ручные маршруты с возможностью отмены.
- **Код:** JSON описывает сохраняемый проект, DOT — его представление для Graphviz. Изменения проверяются перед применением.
- **История:** автосохранение, undo/redo, предпросмотр выбранной версии в отдельном холсте, сравнение и явное восстановление с подтверждением; открытие и сохранение проектов в JSON.
- **Экспорт:** PNG и PDF из приложения, SVG через локальный API (`GET /api/render.svg`); PDF включает предпросмотр готовых страниц, настройку бумаги, пропорциональный масштаб, коррекцию оформления и размещения в отдельной копии, автоматическую многостраничную легенду.
- **ИИ:** создание, изменение и проверка схем через Ollama; настраиваемый системный промпт с Jinja-переменными.

### Движки Graphviz: на что влияет выбор

Выберите **Движок** на панели холста рядом с **Автокомпоновкой** или откройте свойства проекта → **Компоновка → Движок Graphviz**. Оба поля показывают одну настройку проекта. В ручном режиме выбранный движок применяется после нажатия **Автокомпоновка**. Движок определяет расположение компонентов, расстояния между ними и исходные пути связей. Состав объектов и логические связи сохраняются. Поддержка ограничений и группировки различается между движками.

| Движок | Как размещает объекты / когда выбирать |
|---|---|
| `dot` | По уровням иерархии с учётом направления связей. Для архитектурных слоёв и последовательностей взаимодействия. |
| `neato` | Свободное размещение с учётом расстояний в графе. Для небольших сетей без выраженной иерархии. |
| `fdp` | Силовая компоновка: связанные узлы сближаются, остальные раздвигаются. Для сетевых структур и групп. |
| `sfdp` | Масштабируемая силовая компоновка. Для крупных сетей с большим количеством компонентов. |
| `twopi` | Радиальная компоновка: концентрические круги вокруг корневого узла. Для схем с центральным компонентом. |
| `circo` | Кольцевая компоновка. Для циклических связей и кольцевых топологий. |

Принципы алгоритмов описаны в [справке по движкам Graphviz](https://graphviz.org/docs/layouts/); подробнее — [neato](https://graphviz.org/docs/layouts/neato/) и [twopi](https://graphviz.org/docs/layouts/twopi/).

В **автоматическом** режиме используется выбранный движок. Перемещение компонента вручную переключает проект в **ручной** режим: координаты фиксируются, а `neato -n2` пересчитывает связи. Нажмите **Автокомпоновка** на холсте, чтобы выбранный движок снова разместил объекты и пересчитал связи: ручные точки маршрутов сбрасываются, результат вписывается в холст. Операция отменяется через `Cmd+Z`. Режим также можно изменить через **Компоновка → Режим** в настройках проекта.

### Ориентация проекта: LeftRight и UpDown

Поле **Направление** в свойствах проекта задаёт, вдоль какой оси выстраиваются уровни диаграммы:

| Ориентация | Значение | Результат для последовательности A → B → C |
|---|---|---|
| LeftRight — слева направо | `LR` | A слева, B в центре, C справа |
| UpDown — сверху вниз | `TB` | A сверху, B ниже, C внизу |
| Справа налево | `RL` | A справа, B в центре, C слева |
| Снизу вверх | `BT` | A снизу, B выше, C сверху |

LeftRight формирует горизонтальную схему, UpDown — вертикальную. При смене направления пересчитываются размещение уровней и пути связей; источник и получатель каждой связи сохраняются. В Graphviz вертикальное направление называется **TopBottom (`TB`)**.

Эта настройка управляет автоматической иерархической компоновкой **`dot`**. Остальные перечисленные движки не используют `rankdir` для такого выстраивания. При ручном размещении смена направления сохраняет координаты объектов. См. [описание атрибута rankdir](https://graphviz.org/docs/attrs/rankdir/).

### Редактирование кода

В правой панели выберите **JSON**, внесите правки и нажмите **Применить JSON**. До применения или сброса черновика изменения холста заблокированы.

Для **DOT** нажмите **Проверить DOT**: проверка использует актуальное состояние диаграммы и показывает результат без применения изменений. Подтверждение — кнопка **Применить** рядом с проверкой; **Отмена** отклоняет предложение. Неподдерживаемые конструкции и конфликтующие правки сообщаются явно.

### Ollama

Запустите Ollama и загрузите нужную модель. В **Настройки → Ollama и системный промпт…** укажите endpoint (по умолчанию `http://127.0.0.1:11434`) и выберите модель. В нижнем чате доступны режимы **Создать**, **Изменить** и **Проверить**.

Создание и изменение возвращают предложение: просмотрите его и примените, чтобы сохранить новую версию. Проверка возвращает отчёт. Шаблон системного промпта меняется в настройках Ollama, переменные — через **Настройки → Переменные промпта…**; `{{ graphviz_attributes }}` подставляет справку по атрибутам.

## Хранение данных

Все настройки приложения, включая Ollama, шаблон промпта и переменные, тему, навигацию, последний проект и пути JSON-файлов, сохраняются в `~/.config/graphischema/settings.json`. Палитра цветов входит в JSON соответствующего проекта.

Рабочие состояния, проекты, ветки и история находятся в `~/.config/graphischema/projects/graphischema.sqlite3`. Настройки показывают размер SQLite вместе с журналом WAL и SHM. При первом запуске новые версии копируют прежнюю базу из `~/Library/Application Support/GraphiSchema/projects/` (или раннюю `data/`) через SQLite backup, включая подтверждённые записи WAL. Исходная база сохраняется. Старые настройки `GraphiSchema.*` однократно переносятся из macOS preferences.

Python-окружение остаётся в `~/Library/Application Support/GraphiSchema/backend-venv`: это зависимости приложения. JSON-файл переносит текущее состояние схемы; полная история остаётся в SQLite. Для резервной копии при работающем backend используйте SQLite backup; простое копирование файла базы следует выполнять после закрытия приложения.

Для изолированного запуска можно задать `GRAPHI_SCHEMA_CONFIG_DIR`; backend также принимает `GRAPHI_SCHEMA_DATA_DIR`. Автотесты используют временные каталоги и не открывают пользовательскую базу.

## Проекты, окна и ветки

### Стартовое окно

В **GraphiSchema → Настройки… → Стартовое окно** выберите:

- **Последний проект** — вариант по умолчанию: открывает последнюю активную схему и её ветку. Если проект отсутствует, открывается пустой холст.
- **Пустой холст** — каждый запуск начинает с нового временного холста.

Пустой холст не добавляется в менеджер проектов и не создаёт версий. Регистрация в общей SQLite-базе происходит только после первого применённого изменения: добавления объекта, изменения названия, оформления или кода. Имя по умолчанию — `Unnamed-` со случайным идентификатором, например `Unnamed-3e9a71bf42c0`; его можно изменить.

Закрытие пустого окна, просмотр настроек, DOT, истории, экспорт и автоматическая смена системной темы не регистрируют проект и не заменяют последний рабочий проект. Первый снимок содержит уже внесённую правку; `Cmd+Z` может отменить её. **Новая схема** (`Cmd+N`) также открывает временный пустой холст. Автоматическая загрузка базового шаблона не заполняет такой холст; шаблон можно загрузить явно из меню **Файл**.

### Управление проектами

**Файл → Менеджер схем** (`Cmd+Shift+P`) показывает проекты и их ветки. Создавайте пустые схемы (`Cmd+N`), открывайте их здесь или в отдельном окне. **Текущая ветка в новом окне** (`Cmd+Shift+N`) открывает ещё один редактор; название окна содержит проект и ветку. Сохранение и undo/redo изолированы по проекту и ветке. При одновременном редактировании одной ветки независимые правки объединяются, конфликтующие требуют решения.

**Файл → Ветки и коммиты** (`Cmd+Shift+B`) открывает дерево только текущего проекта с временными метками UTC; название окна содержит название и ID проекта. Выбор коммита показывает снимок без применения. От выбранного коммита можно создать ветку и открыть её в текущем или новом окне. **Восстановить** явно создаёт новый снимок в текущей ветке, сохраняя последующие коммиты. **Сохранить коммит** (`Cmd+K`) создаёт именованную контрольную точку, даже если схема не изменилась. Обычная история показывает хронологию текущей ветки вместе с её общими предками. Команды меню относятся к проекту активного основного или вспомогательного окна.

**Форк проекта** в менеджере копирует выбранную ветку в проект с новым ID и отдельной историей. **Импортировать JSON** всегда создаёт независимый проект с новым ID и собственной веткой `main`, даже если исходный ID уже есть в базе. **Открыть проект** продолжает работу с ID, записанным в JSON: совпадающий снимок открывается без новых коммитов; изменённый файл сохраняется в отдельной ветке этого проекта, не перезаписывая прежнее состояние. Для независимой работы с копией файла используйте импорт или форк. Загрузка базового шаблона сохраняет ID и ветку открытого проекта.

### Корзина проектов

В **Файл → Менеджер схем → Проекты** выберите схему и нажмите **В корзину**. Она исчезнет из рабочего списка; её открытые окна переключатся на временные пустые холсты. Ветки и версии сохраняются в общей базе.

В разделе **Корзина** доступны **Восстановить** и **Удалить навсегда…**. Срок хранения — **10 дней (240 часов)** с момента удаления; таблица показывает срок в UTC. Повторное перемещение в корзину не продлевает этот срок. До его окончания восстановление возвращает те же ветки, снимки и их ID; проект затем можно открыть обычным способом.

Просроченные проекты удаляются при запуске backend и раз в минуту во время работы, а также при открытии корзины. Если приложение закрыто, очистка произойдёт при следующем запуске. Окончательное удаление раньше срока требует подтверждения.

Окончательно удаляются запись проекта, все его ветки и снимки с содержимым схемы и палитрой, старые соответствия ревизий, undo/redo, настройки темы и привязки к файлам. Родительский проект удаляемого форка сохраняется. Другие самостоятельные проекты, включая дочерние форки, также сохраняются; ссылка на удалённый источник очищается. Отдельно экспортированные JSON-файлы и резервные копии остаются самостоятельными файлами и автоматически не удаляются.

Версионирование реализовано внутри единой SQLite-базы, Git для схем не используется. Таблица `projects` хранит проекты, `branches` — их ветки и указатели на последние снимки, `versions` — JSON-снимки, родителей, даты и сообщения. Все выборки истории ограничены `project_id`; SQLite запрещает назначать ветке или коммиту предка из другого проекта. Номер коммита в интерфейсе отсчитывается с **№1 отдельно для каждого проекта** и общий для его веток. Внутренние ID записей уникальны во всей базе. При обновлении старые ID, даты и связи сохраняются, добавляется нумерация внутри проекта.

Неприменённый JSON/DOT нужно применить или сбросить перед заменой текущего проекта; выход с неприменённым кодом требует явного выбора.

## Группы связей и направляющие

Удерживайте `Shift` при выборе связей на холсте или в левом перечне. Рамка выделения выбирает связи, если внутри неё нет компонентов. Свойства, меню ПКМ и окна цветов применяют оформление ко всей группе одной операцией: цвет, толщина, стиль, маршрут, наконечники, направление. Группу можно копировать с новыми ID, удалить и отменить действие.

**Вид → Помощь в выравнивании** (`Cmd+Shift+A`) включает притягивание границ и центров при перемещении. Розовые направляющие показывают совпадения; допуск — 6 экранных точек при любом масштабе. `Shift` сохраняет движение по одной оси.

Длительное нажатие (около 0,6 с) открывает текст фигуры, связи или контейнера рядом с курсором. Перемещение указателя отменяет вызов. Кривые с фиксированными портами и точками пути сглаживаются общим геометрическим слоем приложения; прямоугольные маршруты сохраняют прямые углы.

## Для разработки

Запуск backend отдельно от приложения:

```bash
uv sync --extra dev
uv run python -m graphischema.server --host 127.0.0.1 --port 8000
```

Документация API этого сервера: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Проверки из корня репозитория после установки dev-зависимостей:

```bash
uv run pytest
./scripts/test_native_ui.sh
./scripts/test_native_interaction.sh
./scripts/test_native_projects.sh
./scripts/test_native_png.sh
./scripts/test_arrows.sh
```

`test_native_interaction.sh` проверяет контуры всех фигур, масштаб и растягивание, реально отрисованный текст, сохранение фокуса при вводе и положение окон. Запускайте нативные проверки в графическом сеансе macOS. При расхождении с растровой отрисовкой сохраняется снимок `dist/interaction-debug/failure.png`.

`test_native_png.sh` использует временные настройки и backend: проверяет легенду, группы, размеры, DPI, прозрачность, повторное открытие окна, восстановление после ошибки и автоматическую подгонку больших схем. Примеры результата и снимок окна сохраняются в `dist/quality/png-export`.

Подробная матрица сценариев и критериев — в [docs/testing.md](docs/testing.md).

Для распространения используйте [скрипт сборки](scripts/build_macos.sh) в режиме `distribution` с `GRAPHI_SCHEMA_SIGN_IDENTITY` и [скрипт notarization](scripts/notarize_macos.sh) с `GRAPHI_SCHEMA_NOTARY_PROFILE`. Режим `local` использует ad hoc-подпись.

Результаты последней проверки — в [docs/quality-report.md](docs/quality-report.md).
