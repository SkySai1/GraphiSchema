# GraphiSchema

Нативное локальное приложение macOS для проектирования архитектурных диаграмм. Интерфейс и холст написаны на Swift с AppKit, общая JSON-структура проекта и операции с ней обслуживаются Python/FastAPI, а Graphviz выполняет компоновку и маршрутизацию связей. SVG доступен для экспорта; на холсте геометрия рисуется нативно.

## Требования

- macOS 13 или новее.
- Swift 5.9+ и Xcode Command Line Tools.
- `uv` для Python backend.
- Graphviz (`dot`) для автоматической компоновки. Без него используется локальная детерминированная компоновка.
- `rsvg-convert` (`brew install librsvg`) для PNG: растеризует общий SVG со всеми фигурами коллекций и ручными маршрутами.

## Сборка приложения

```bash
./scripts/build_macos.sh local
open "dist/GraphiSchema.app"
```

Скрипт собирает нативный AppKit release target, упаковывает локальный backend и устанавливает его Python-зависимости в `~/Library/Application Support/GraphiSchema/backend-venv`. SwiftPM и uv кэшируют сборочные файлы в `$TMPDIR/graphischema-build-cache`. При запуске приложение само запускает backend на loopback-интерфейсе; если у пользователя ещё нет Python-зависимостей, `uv` устанавливает их из `uv.lock` при первом запуске. Поэтому для запуска на другой машине требуется `uv`, а локальный Ollama остаётся необязательным. Текущий проект и снимки версий хранятся в `~/Library/Application Support/GraphiSchema/projects/graphischema.sqlite3`.

Distribution-сборка подписывается Developer ID, использует hardened runtime и создаёт отдельный ZIP. Для неё нужны Developer ID Application сертификат и сохранённый профиль `notarytool` в Keychain:

```bash
GRAPHI_SCHEMA_SIGN_IDENTITY="Developer ID Application: ..." ./scripts/build_macos.sh distribution
GRAPHI_SCHEMA_NOTARY_PROFILE="graphischema-notary" ./scripts/notarize_macos.sh
```

Скрипт notarization отправляет ZIP в Apple, stapling-ует билет к приложению и пересобирает ZIP. См. [инструкции Apple по notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

Рабочее окно постоянно разделено на три панели: слева библиотека из шаблонов и стандартных фигур (круг, квадрат, прямоугольник, эллипс, ромб, треугольник, шестиугольник и стрелки) с поиском и перетаскиванием на холст, в центре холст и чат Ollama внизу, справа редактор JSON/DOT. Дополнительные SVG-значки библиотек работают локально и взяты из коллекций [Tabler Icons](https://github.com/tabler/tabler-icons) и [Lucide](https://github.com/lucide-icons/lucide); лицензии включены в `resources/object-library`. JSON — сохраняемая структура проекта; после правок нажмите «Применить JSON», чтобы проверить данные и обновить холст. Пока черновик не применён или не сброшен, изменения холста заблокированы. В чате выберите создание, изменение или проверку. Проверка возвращает отчёт без изменения проекта; генерация и изменение показывают JSON-предложение справа. Применение предложения сохраняет новую версию проекта, отмена оставляет текущую версию нетронутой. Endpoint, модель и системный промпт задаются через «Настройки ИИ» или кнопку настроек чата.

Перетаскивайте компоненты из палитры и перемещайте их мышью. У выбранной фигуры справа расположены два одинаковых круглых элемента управления: горизонтальная стрелка создаёт связь перетаскиванием на другой объект, нижние два треугольника меняют размер. Двигайте указатель по диагонали вправо-вниз для увеличения или влево-вверх для уменьшения. Нажмите на линию, чтобы выбрать её: зелёная точка у начала и оранжевая у конца позволяют перетащить связь к другому объекту; точки пути добавляются двойным щелчком. В контекстном меню связи можно сбросить её маршрут, а кнопка «Оптимизировать линии» очищает ручные маршруты сразу у всех связей. Маркер выбранного контейнера меняет его отступ (4–48 pt); пустой контейнер следует за курсором во время перемещения и позволяет менять размер. Используйте `Option` + перетаскивание для панорамирования и жест щипка либо `Command` + прокрутка для масштаба. Кнопка «Вписать» показывает всю диаграмму; сетку можно включать и выключать. Свободный узел прикрепляется к контейнеру при отпускании внутри его границ. Перемещение вложенного узла сохраняет его принадлежность и изменяет размеры контейнера вокруг содержимого. Для отсоединения используйте команду «Извлечь из контейнера» в меню ПКМ; координаты узла сохраняются. Правый щелчок по узлу позволяет задать z-index или переместить его вперёд/назад; больший индекс рисуется поверх меньшего. Это порядок рендерера GraphiSchema, Graphviz не управляет слоями отображения. Тачпад по умолчанию двигает холст вслед за пальцами по обеим осям; в настройках доступно противоположное направление. Перемещение узла или контейнера переводит диаграмму в ручной режим: `neato -n2` сохраняет координаты и рассчитывает маршруты связей. `Command+Z` отменяет, `Command+Y` повторяет изменения. Меню macOS «Файл» открывает JSON-проект, сохраняет его и загружает базовый шаблон; «Настройки» содержит Ollama, переменные промпта и режим темы.

Автосохранение упорядочивает записи, а backend объединяет независимые изменения из нескольких открытых окон — в том числе от старых клиентов. Если разные окна изменили одно и то же поле, GraphiSchema останавливает такую запись, чтобы не затереть данные. При запуске приложение проверяет поддержку этого механизма и не подключается к несовместимому старому backend на порту 8765. Хранилище при старте нормализует ревизии после изменений схемы и сохраняет соответствия устаревших ревизий.

В редакторе DOT можно менять поддерживаемые параметры модели, добавлять и удалять узлы, контейнеры и связи. «Проверить DOT» разбирает код, сообщает о неподдерживаемых атрибутах и показывает кандидат рядом с исходником. Пока кандидат не применён, текущая ревизия проекта не меняется. После проверки его можно применить или отменить. Произвольные Graphviz-конструкции, которые нельзя отобразить в JSON-модели, явно отклоняются.

Панель «Ollama» подключается к `http://127.0.0.1:11434` по умолчанию. Endpoint, модель, системный промпт, температуру, размер контекста и тайм-аут можно изменить; настройки хранятся локально в пользовательских настройках macOS. Режимы «Создать» и «Изменить» возвращают проверяемое предложение, которое отображается на холсте и не сохраняется до явного применения. Режим «Проверить» возвращает только отчёт и не меняет диаграмму. Вызовы требуют запущенного Ollama и установленной модели.

Сборка не подписана и предназначена для локальной разработки. Исходники backend также можно запустить отдельно:

```bash
uv sync --extra dev
uv run uvicorn graphischema.api:app --app-dir backend --reload
```

REST API и справка доступны на `/docs` при запущенном backend.

Маршрут выбирается в «Стиль»: для проекта — «Маршрут связей», для стрелки — «Маршрут этой связи». Доступны прямые, косые и прямоугольные линии. Отдельная стрелка может наследовать настройку диаграммы или иметь свой маршрут. У выбранной линии потяните синий маркер, чтобы изменить путь; двойной щелчок по линии добавляет точку. «Сбросить точки пути» возвращает автоматический маршрут. Добавление ручных точек фиксирует текущие координаты объектов и включает ручной режим. Привязки источника/цели: ближайшая граница фигуры, сторона, направление или вершина. Координаты, привязки и маршрут сохраняются в JSON и версиях.

Graphviz рассчитывает положение объектов и исходные пути. Общий слой геометрии уточняет концы по видимому контуру, рисует наконечники и применяет пользовательские точки; тот же контур используется для попадания мышью, Swift-холста и SVG/PNG. У Graphviz [splines=ortho есть ограничения портов и подписей](https://graphviz.org/docs/attrs/splines/), поэтому окончательные привязки выполняет геометрический слой. Поддерживаются ближайший контур, стороны и вершины иконки; произвольное прикрепление к любой точке ребра произвольного SVG не является атрибутом Graphviz и обрабатывается редактором. DOT сохраняет `headport`/`tailport`, а параметры фигур и ручных путей — в расширениях `gs_icon`, `gs_source_port`, `gs_target_port`, `gs_routing`, `gs_waypoints`. Эти расширения принадлежат редактору, сам Graphviz их не отображает. `splines=curved` включает кривые маршруты.

Добавленные из коллекций компоненты сохраняют SVG-фигуру и исходные пропорции. Масштабирование мышью сохраняет пропорции; удерживайте Shift для свободного изменения ширины и высоты. В свойствах используйте «Коллекция» и «Фигура» для замены с сохранением ID, названия и связей. Общие векторные контуры находятся в `backend/graphischema/resources/icon_geometry.json`; при изменении SVG-библиотеки пересоздайте их командой `uv run scripts/generate_icon_geometry.py`. Зависимость парсера нужна только этому скрипту.

По умолчанию точный тачпад работает в инверсном режиме: движение пальцев вверх двигает холст вниз. Системное направление колеса мыши сохраняется. В свойствах проекта можно выбрать системную навигацию. Щипок и `Command` + прокрутка меняют масштаб, `Option` + перетаскивание панорамирует. Кнопка с луной в верхней панели переключает тему всех окон: дневную или ночную с тёмно-фиолетовым холстом и контрастными подписями. Собственные цвета фигур сохраняются.

В «Настройки ИИ» системный промпт поддерживает [Jinja](https://jinja.palletsprojects.com/en/stable/sandbox/): `{{ graphviz_attributes }}` подставляет встроенный справочник атрибутов и правил размещения. Кнопка «Переменные…» открывает отдельный редактор: создание, переименование, изменение и удаление пользовательских переменных; встроенный справочник можно восстановить кнопкой «По умолчанию». Настройки сохраняются локально. «Предпросмотр промпта» проверяет и показывает результат без вызова Ollama. Переменные подставляются во всех трёх режимах ИИ. Разрешены текстовые подстановки, условия и фильтры `trim`, `upper`, `lower`, `default`, `replace`; неизвестные переменные, циклы, вызовы и доступ к объектам вызывают понятную ошибку.

Jinja2 установлен через `uv` и закреплён в `pyproject.toml`/`uv.lock`. Для установки через pip есть `requirements.txt`; обновление: `uv export --no-dev --no-emit-project --no-hashes --format requirements-txt --output-file requirements.txt`.

Карточки палитры и загруженные SVG переиспользуются при переключении коллекций. Иконки видимых карточек читаются в фоне; изменения диаграммы не пересобирают коллекцию. Новые объекты и изменения координат появляются на холсте сразу, затем уточняется геометрия Graphviz. Высота окна свойств зависит от выбранного элемента; для длинных форм доступна прокрутка. Поля прижаты к шапке с зазором 19 pt, включая увеличение высоты окна.

## Проверки

```bash
uv run pytest
swift build --package-path native
./scripts/test_native_ui.sh
./scripts/test_arrows.sh
```

Python-тесты проверяют модель, валидацию и совместимость DOT, SVG/PNG, геометрию холста, SQLite-миграцию и версии, undo/redo, Ollama-операции, API и JSON import/export с вложенными контейнерами. Для Ollama используются заглушки, поэтому тесты не требуют запущенной модели. `test_native_ui.sh` проверяет редактор, замену фигуры, привязки и перетаскивание маршрута мышью, темы, навигацию, переменные и их восстановление. При ошибке тест заканчивается ненулевым кодом без crash report; временные настройки восстанавливаются. Флаг `--startup-smoke-test` запускает окно, собственный backend и загрузку Graphviz в отдельном временном проекте; после проверки приложение закрывается и удаляет тестовое хранилище. Пример: `open -n -W -a "$PWD/dist/GraphiSchema.app" --args --startup-smoke-test`. Graphviz-тесты пропускаются, если `dot` не установлен.

`test_native_ui.sh` также проверяет отрисованные пиксели пустого контейнера во время перетаскивания через реальный контроллер, сохранение членства при перемещении и явное извлечение через ПКМ, 32 сочетания физического направления жеста и настроек прокрутки, увеличение/уменьшение через видимые круглые маркеры и зазор свойств не более 2em при изменении высоты окна. Снимки этих сценариев сохраняются при указании `GRAPHI_SCHEMA_UI_ARTIFACT_DIR`.

`test_arrows.sh` исследует положение линии и наконечников в 156 схемах, сравнивает SVG с нативной геометрией при трёх масштабах и проверяет фактические пиксели AppKit. CSV с координатами, SVG и PNG сохраняются в `dist/arrow-debug/current/`. Причины ошибок, точные условия и допуски описаны в [руководстве по отладке стрелок](docs/arrow-debugging.md).
