# Отладка стыка линии и наконечника

Регрессионный набор запускается на macOS без XCTest:

```bash
./scripts/test_arrows.sh
```

Результаты записываются в `dist/arrow-debug/current/`. Каталог можно изменить
через `GRAPHI_SCHEMA_ARROW_OUTPUT`, каталог сборки — через
`GRAPHI_SCHEMA_BUILD_CACHE`. Для проверки только нативной части собранный
debug executable принимает аргумент `--arrow-regression-test`: без дополнительных
переменных используются 20 сохранённых схем и набор точных координат из
`native/Tests/GraphiSchemaTests/Fixtures/`.

## Независимые наблюдения

1. `scripts/diagnose_arrows.py` разбирает **реальные SVG-команды** рендерера.
   Центр основания треугольника вычисляется как средняя точка двух задних
   вершин. Положение линии берётся из её собственного пути, угол подхода —
   из последнего ненулевого сегмента. Наблюдатель не вызывает функции расчёта
   наконечников. Для пунктирных линий учитывается отдельный сплошной подход.
2. Нативный тест проверяет команды, которые используются `DiagramCanvasView`
   для отрисовки, сравнивает их с SVG и с известными координатами. Затем AppKit
   действительно растеризует холст; цветовые выборки проверяют непрерывность
   подхода с шагом 0,25 pt и допуском в один физический пиксель.
3. Отдельный отрицательный тест сохраняет сломанный стык с коротким последним
   сегментом. Наблюдатель обязан обнаружить расхождение, а не просто вернуть
   тот же `atan2`, что используется рендерером.

Матрица содержит 156 схем: ручное размещение, шесть движков Graphviz
(`dot`, `neato`, `fdp`, `sfdp`, `twopi`, `circo`), направления LR/RL/TB/BT,
восемь взаимных положений объектов, прямой/угловой/прямоугольный/кривой
маршруты, закреплённые грани и вершины, иконки, петли, короткие изгибы и
узкие промежутки. Нативная часть исследует каждый конец при масштабах
12, 72 и 220 pt на единицу координат диаграммы: всего 936 наблюдений.
Ещё 1 792 стыка проверяются для семи видов наконечников, восьми направлений,
четырёх толщин и четырёх маршрутов. 54 нативные растеризации проверяют
сплошные, пунктирные и точечные линии.

## Обнаруженные причины

- Линия продолжалась до вершины наконечника. На прямом длинном сегменте
  заливка треугольника скрывала это. При коротком сегменте или изгибе путь
  пересекал бок треугольника, вместо центра основания.
- При первом обновлении холст отбрасывал полученный маршрут, поскольку ещё
  не было предыдущей связи для сравнения. Затем готовую дискретизированную
  кривую можно было повторно интерпретировать как контрольные точки Bézier.
- У закреплённой верхней грани прямоугольный маршрут мог идти вдоль границы.
  Заливка объекта скрывала часть линии подхода к наконечнику.

## Точные координаты воспроизводимого случая

Схема `short-elbow-straight`, целевой конец, SVG, единицы pt:

| Измерение | До исправления | После исправления |
|---|---|---|
| Вершина наконечника | (265,60; 68,32) | (265,60; 68,32) |
| Центр основания | (257,60; 68,32) | (257,60; 68,32) |
| Конец линии | (265,60; 68,32) | (257,60; 68,32) |
| Пересечение плоскости основания | (257,60; 35,20) | (257,60; 68,32) |
| Боковое отклонение | 33,12 pt | 0 pt |

В AppKit для того же случая при масштабе 72 измерены вершина
(277,60; 186,88), основание (269,60; 186,88), конец линии (269,60; 186,88).
Различие абсолютных координат связано с отступами и направлением оси Y;
относительные координаты обоих рендереров совпадают.

В исходных 152 схемах максимальное боковое отклонение составляло 33,12 pt.
После исправления максимальная погрешность стыка в SVG — 0,000071 pt
(округление координат до четырёх знаков), угол стыковки — менее 0,005°.
В нативных численных измерениях погрешность равна 0 pt.

## Зафиксированные условия

- Вершина наконечника сохраняет координаты точки крепления на контуре.
- Конец линии совпадает с **центром фактического основания**: допуск
  0,001 pt для сериализованного SVG и 0,0000001 pt для нативной геометрии.
- Последний сегмент входит сзади: его вектор коллинеарен оси наконечника и
  имеет положительное скалярное произведение с ней.
- Перед основанием остаётся прямой участок; фаза пунктира не создаёт зазор.
- На коротких связях размеры обоих наконечников уменьшаются согласованно.
- Подходы к закреплённым граням находятся снаружи заливки и уменьшаются
  в узких промежутках между объектами.
- Готовые маршруты с `normalized: true` используются без повторного
  построения. Составные исходные кривые Bézier сохраняют все сегменты.
- Изменение цвета сохраняет маршрут; замена фигуры и редактирование
  контрольных точек пересчитывают геометрию до ответа backend.
- Выделение линии мышью использует её скорректированный видимый путь.

## Артефакты

- `measurements.csv`: координаты конца линии, вершины, основания, угол и
  боковое отклонение каждого SVG-наконечника.
- `summary.json`: максимальные ошибки и число нарушений.
- `native-fixtures.json`: исходные проекты, реальные координаты Graphviz и
  независимо измеренные параметры SVG для сравнения со Swift.
- `overview.svg` и SVG отдельных случаев: визуальная матрица.
- `native/native-measurements.csv`: координаты нативных стыков при трёх масштабах.
- `native/*.png`: фактическая растеризация AppKit характерных случаев.
- `native/failures.log`: точные проверки, которые не прошли.
